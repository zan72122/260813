# R2 — 独立レビュー: 4歳児UX / 画面品質 / ゲーム性

担当: Sonnet 5 (R2, 読み取り専用)。基準: `docs/PRODUCT_SPEC.md`。
方法: (1) `artifacts/screenshots/` の製品スクショ01〜10・dev-*全件をReadで目視。
(2) `npx vite preview --port 4175` を起動し、Playwright(`executablePath: /opt/pw-browsers/chromium`,
390x844 / 844x390, 実ポインタでのdrag/swipe)で title→あそぶ→intro→hide(実ドラッグ含む)
→gate(実スワイプ)→seek→album→「もういちど」の一周を実行、加えてhide画面で6秒無操作の
ヒント発火テストを実施。コンソール/pageerrorは0件、一周を通じてクラッシュ・スタールなし。
(3) 挙動の根拠づけのため関連ソース(`src/ui/screens/*.ts`, `src/ui/components/*.ts`,
`src/game/hints.ts`, `src/scene/elephant/behaviors/*.ts`, `src/styles.css`)を該当箇所のみ確認。
追加スクショはscratchpadに保存(`r2-*.png`、リポジトリ外)。

## 発見一覧

### R2-01 — hide画面のドラッグ中ゴーストが指先を中心に重なり、吸着先(変化点)を隠す
- **severity**: major
- **confidence**: high
- **evidence**: `src/ui/components/foodTray.ts:65-75`(`ghost.style.left/top = ev.clientX/clientY`、
  垂直オフセットなし)、`src/styles.css:537-543`
  ```css
  .food-tray__ghost {
    position: fixed;
    transform: translate(-50%, -50%) scale(1.08); /* 指先座標にそのまま中心を重ねる */
  }
  ```
  ゴースト画像(76px×1.15≈87px)が指のclientX/Yに`translate(-50%,-50%)`でぴったり重なる。
  実機ドラッグ確認(`r2-drag-mid.png`, `r2-drag-near-spot.png`)でも、食材アイコンは常に
  指の直下に表示され、最終的に置きたい場所(吸着スポットの地面)は指とゴースト自身に
  隠れて見えない。4歳児の指/親指は大人よりスポットに対して相対的に大きく、狙う瞬間に
  一番見たい「置き先の地面」が最も隠れやすい設計になっている。
- **suggested fix**: ゴーストを指先より一定量(例: 60–80px)上にオフセットして表示し、
  指自体が置き先を覆わないようにする(スマホの定番「ドラッグ中は少し浮かせる」パターン)。

### R2-02 — 無操作ヒントが対象(スポット)と視覚的に結びついていない。仕様が求める「対象の微振動・局所光」が未実装
- **severity**: major
- **confidence**: high
- **evidence**: `src/game/hints.ts`は`getSpotId()`で対象スポットIDを`hint:show`ペイロードに
  含めているが、`src/ui/app.ts:134-138`のリスナーは`spotId`を一切使わず
  `hintBubble.pulse()`を呼ぶだけ。`src/ui/components/hintBubble.ts`のバブルは
  `.hint-bubble { top: calc(var(--safe-top)+90px); left:50% }`(`src/styles.css:785-793`)で
  常に画面上部中央に固定表示される「指さし風アイコン」。
  実機確認: hide画面で6秒無操作にすると、バブルは家(飼育舎)の屋根の上あたりに表示され
  (`r2-hide-hint.png`)、実際に隠すべき3スポット(石垣=左, 砂場の輪=中央下寄り, 高い木=右)の
  どれとも視覚的に結びつかない。`docs/PRODUCT_SPEC.md`の4歳児UX原則にある
  「対象の微振動、局所光」の実装は`highlightSpot()`(ドラッグ中のみ使用、`src/ui/screens/hide.ts:141`)
  に留まり、無操作ヒント経路からは呼ばれていない。
- **suggested fix**: `hint:show`のspotId受信時に、その対象スポットへ`ctx.world.highlightSpot(spotId)`
  を短時間ON/OFFする、または対象の画面座標へバブルを追従させる。汎用の「指さし」だけでなく
  対象そのものが光る/揺れることで、迷っている子どもの視線を実際の場所へ誘導できる。

### R2-03 — 採食5行動のクローズアップが接写しすぎて場所の手がかりが消え、静止画では行動同士が似て見える
- **severity**: minor
- **confidence**: medium(静止画のみの評価。アニメーション自体の質は未確認)
- **evidence**: `artifacts/screenshots/04-dig-sand.png`・`05-reach-pipe.png`・`06-peel-banana.png`は
  いずれも「ゾウの顔と鼻が画面の大半を占め、脚の間に小さく餌が光る」という酷似した構図。
  特に`05-reach-pipe.png`は土管の質感/丸みがほぼ見えず(暗い影の帯のみ)、`土管に鼻を伸ばす`
  行動だと単体では判別しづらい。一方、同じ地点をやや引いて撮った`dev-s3b-pipe.png`
  (土管の円筒と穴が明瞭)や`dev-s3b-probe.png`(石垣がはっきり見える)では場所の手がかりが
  十分残っており、環境自体は5スポットとも識別可能な作りになっている
  (`10-landscape-overview.png`で石垣/根本/砂の輪/土管/高木が一望できる)。
  つまり問題は環境デザインではなく、行動再生時の接写カメラ(`behavior:<id>`プリセット、
  `src/scene/elephant/behaviors/support.ts`の`cutCamera`)が寄りすぎている点にある。
- **suggested fix**: 特に`reach-pipe`と`dig-sand`/`peel-banana`について、行動接写の画角を
  `dev-s3b-*`程度までわずかに引き、地形の識別要素(土管の円筒、石垣の積み方、根本の形)を
  画面内に残す。

### R2-04 — seek中、飼育員とカートがゾウと同時にフレームへ残り続ける場面がある
- **severity**: minor
- **confidence**: medium
- **evidence**: `r2-seek-start.png` / `r2-seek-mid.png`(実機取得)、`artifacts/screenshots/dev-s4-seek.png`
  いずれもゾウが画面奥から歩いてくる間、手前に飼育員+カートがそのまま静止して映り続ける。
  `docs/PRODUCT_SPEC.md`の「一場面一動詞。主役は常に1つ」に対し、seekは本来ゾウ単独が
  主役であるべき場面。飼育員は小さく動きも少ないため致命的な混乱は生まないが、
  「探す→見つける」の主役がゾウであることをより明確にできる余地がある。
- **suggested fix**: ゲート開放後、飼育員をフレーム外へ退出させる、またはoverviewカメラを
  ゾウ寄りにトリミングする。

### R2-05 — 砂・樹皮などの表面が平坦で、仕様が意図する「触りたくなる質感」までは届いていない
- **severity**: minor / info
- **confidence**: medium(様式判断であり不具合ではない)
- **evidence**: `dev-s3b-dig.png`の砂は単色グラデーションでほぼ粒感なし、`dev-s3b-banana.png`の
  ガジュマルの幹・根も単色フラットで木目/繊維が見えない。葉は多面体(宝石的)スタイルで
  統一されており、それ自体は破綻なく好感が持てるビジュアル言語だが、
  `docs/PRODUCT_SPEC.md`が名指しする「光・砂・葉・バナナ繊維の触りたくなる質感」の
  観点では、まだ平面的。
- **suggested fix**: 既存のローポリ様式を崩さない範囲で、砂の粒状ディテール(既存のdecal/dust
  パーティクルの活用)やバナナ茎の縦筋テクスチャなど、ごく軽量な表面変化を足す。

### R2-06 — 音・振動・実機タッチ操作感は未確認
- **severity**: info
- **confidence**: n/a(スクリーンショット/Playwrightマウス操作では検証不能)
- **evidence**: `dev-s5-settings.png`で「おと」トグルの存在は確認できるが、実際の音質・
  タイミング・触覚振動・実機(iOS Safari)でのタッチ精度は本レビューの手法では確認できない。
- **suggested fix**: 実機での音・振動レビューを別途実施することを推奨(本レビューの対象外として明記)。

## 良い点(維持すべき品質)

1. **一周を通じてクラッシュ・スタールなし**: title→intro→hide(実ドラッグ)→gate(実スワイプ)
   →seek→album→「もういちど」の完全なプレイスルーでconsole/pageerrorは0件。実装が安定している。
2. **リプレイ導線が仕様(2タップ以内)を上回る1タップ**: album画面の「もういちど」を押すと
   即座にhide画面へ戻ることを実機確認(`replay via 'もういちど' worked: 1 tap from album`)。
3. **タッチ対象は仕様(64–96px相当)を満たす**: 食材トレイのスロットは実測92×92px
   (`tray slot box`)、ゲートレバーは80×80px。いずれも視認・実測で余裕を持って基準を超えている。
4. **ドラッグ中の吸着フィードバックが機能している**: スポット近接時に地面が柔らかく金色に光る
   様子を実機ドラッグで確認(`r2-drag-mid.png`)。広めの吸着半径(`SNAP_SLACK`)も含め、
   4歳児向けの「狙いが多少ズレても拾ってくれる」設計が実際に動いている。
5. **「汎用AI風UI」を回避できている**: 紫グラデーションや長方形カード羅列は見当たらず、
   暖色(コーラル/クリーム)・大きな角丸ボタン・手描き風グリフアイコン(汎用アイコンセットでない)
   で統一されている(01-title.png, 09-album.png, dev-s5-settings.png)。文章もひらがな中心で短い。
6. **ゾウの造形が親しみやすい**: 丸みを帯びた体型・小さな黒い点目・穏やかな表情で、
   牙や吊り上がった目のような威圧的要素はどのスクショにも見当たらない
   (dev-s3-elephant-idle.png, 03-gate-elephant.png)。
7. **intro(飼育員入場)は文章説明なし・約2.2秒と短く、タップ必須ではない**:
   `src/scene/world.ts:410`の`duration = 2.2`秒、`src/ui/screens/intro.ts`はタップは
   任意スキップであり自動的に`hide`へ進む。4歳児に長すぎる待機にはなっていない。
   同様にsniff(0.55–0.9秒)・入場(0.9–2秒)も短時間に収まっている。
8. **hide画面の環境は5スポットが一望でき、隠し場所を自分で選ぶ手がかりがある**:
   `10-landscape-overview.png`で石垣・ガジュマルの根本・砂の輪・土管・高木が同一画面に
   収まり、隠す位置の候補が視覚的に把握できる。placeInto()は`goTo(spot:${spotId})`で
   隠す瞬間にその場所へカメラを寄せており(`src/ui/screens/hide.ts:181`)、
   「隠した場所」を後で「見つかる場所」として再認識しやすい構造になっている。
9. **非公式表示が子ども向け画面を邪魔せず適切に配置**: 情報パネルは「i」ボタンからのみ開き、
   「沖縄こどもの国の公式ゲームではありません」の明記あり(`info-panel.png`)。
   タイトル画面自体は子ども向けにシンプルなまま保たれている。

## 最重要5件

1. **R2-01(major)**: hideドラッグ中、ゴーストが指先に正確重なり吸着先の地面を隠す
   (`translate(-50%,-50%)`にオフセットなし) — 核心操作の視認性に直結。
2. **R2-02(major)**: 無操作ヒントが対象スポットと結びつかず、仕様が求める「対象の微振動・局所光」が未実装
   (常に画面上部固定の汎用「指さし」バブルのみ)。
3. **R2-03(minor)**: 5行動の接写が寄りすぎて場所の手がかりが消え、特に`reach-pipe`が静止画で
   識別しにくい(環境自体は5スポットとも識別可能なため、カメラ画角の調整で解決可能)。
4. **R2-04(minor)**: seek中、飼育員+カートがゾウと同時にフレームへ残り、主役が一瞬わかりにくい。
5. **R2-05(minor/info)**: 砂・樹皮の質感が平坦で、仕様の「触りたくなる質感」目標にはあと一歩。

以上。critical(即壊れる/致命的)に該当する発見はなし。

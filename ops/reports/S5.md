# S5 レポート — 音/せってい/保存/PWA/アクセシビリティ

## 1. 音(`src/audio/`、全てWebAudio合成、外部音源ファイル0)

- `engine.ts`: `AudioContext`は`unlock()`が初めて呼ばれるまで生成しない(iOS Safari対策)。`unlock()`は
  resume()+1サンプルの無音バッファ再生を行う。`masterGain`(固定0.6、圧縮/リミッタ代わり)を経由して
  sfx/ambienceが接続される。`document.visibilitychange`に自動連動してsuspend/resume(タブを閉じずに
  離れた間はCPU/バッテリを使わない)。
- `sfx.ts`: `SfxId`全11種を個別設計。共通ヘルパー(`tone`/`noiseBurst`/`envGain`)の上に、行動ごとに
  異なる波形・フィルタ・粒立てで質感を作った(音色一覧は下表)。`play(id, volumeScale?)`で個々の
  発音を控えめにできる(probe-gapの「小さめ」演出等)。`playPulleySqueak()`はSfxId契約に無い
  high-branch専用の装飾音(ui-tapとは中心周波数・波形が異なり、流用感を避けている)。
- `ambience.ts`: フィルタ付きループノイズ(そよ風、0.07Hzの遅いLFOでカットオフをゆらす)+
  3.5〜9.5秒間隔でランダムに挿入される鳥のさえずり(サイン波2〜3音の短い装飾音)。sfxより
  控えめな相対音量(マスタの0.35倍)。`setVolume(v)`で即時反映。
- `index.ts`: `createAudioSystem()`が`AudioApi`(docs/INTERFACES.md契約どおり)を組み立て、
  `bindEvents(events)`がゲームイベントを購読して音を鳴らす。テスト向けに`AudioSystemDeps`で
  engine/sfx/ambienceを差し替え可能(`tests/unit/audio-mapping.test.ts`が実際に利用)。

| sand-cover | バンドパスノイズburst(2200Hz→1500Hz)を2回、ずらして「ザッ、ザッ」 |
| gate-open | ローパスの鋸波sweep(72→36Hz)+同時に低いノイズの唸り、1.1秒の「ゴロゴロ」 |
| trunk-pipe | バンドパスノイズ(480Hz, Q1.4)、立ち上がりを緩やかにした「フーッ」 |
| leaf-rustle | ハイパスノイズの粒6個、間隔と音量をランダムに散らした「シャラシャラ」 |
| banana-peel | ノコギリ波の粒5個(ピッチ上昇260→520Hz付近)+擦れノイズ、「ミリミリッ」 |
| branch-creak | 低いのこぎり波(88→66→102→64Hz、ゆっくり揺らぐ)をローパスで丸めた「ギィィ」 |
| branch-snap | 短いbandpassノイズ(30ms)+矩形波アタック(220→75Hz急降下)、「バキッ」 |
| found-chime | サイン523.25Hz→783.99Hz(五度)+わずかなトライアングル倍音、優しい2音チャイム |
| ui-tap | サイン640Hz、50ms、控えめな「コッ」 |
| elephant-rumble | サイン38Hz+41Hz+4.5HzのLFOでゆらす、1.6秒の超低周波の穏やかな鳴き |
| (装飾)pulleySqueak | bandpassノイズ(2600Hz, Q5)+矩形波(1500→2100Hz)、high-branch専用「キュッ」 |

### イベント→SfxIdマッピング表

| イベント | 条件 | 音 |
|---|---|---|
| `food:hidden` | spotId=stone-gap | food-tuck |
| `food:hidden` | spotId=sand | sand-cover |
| `food:hidden` | spotId=pipe | trunk-pipe(転用の転がり音、仕様どおり) |
| `food:hidden` | spotId=banyan-root | leaf-rustle |
| `food:hidden` | spotId=high-branch | leaf-rustle + 130ms後にpulleySqueak |
| `gate:opened` | – | gate-open |
| `behavior:start` | probe-gap | leaf-rustle(0.5)+trunk-pipe(0.4)、同時・控えめ |
| `behavior:start` | dig-sand | sand-cover を0/260/520msで3連打 |
| `behavior:start` | reach-pipe | trunk-pipe |
| `behavior:start` | peel-banana | banana-peel を0/240msで2回(繰り返し) |
| `behavior:start` | break-branch | branch-creakを即再生+2.8秒後にbranch-snapを近似タイマーで予約 |
| `behavior:complete` | behaviorId=break-branch かつ予約タイマー未発火 | タイマーを取り消しbranch-snapを即再生してからfound-chime |
| `behavior:complete` | 全behaviorId共通 | found-chime、35%の確率で220ms後にelephant-rumble(0.7) |
| ui操作(button/role=button押下) | – | ui-tap(document委譲の1リスナー、main.tsの`bindUiTapSounds`) |

break-branchの「折れる瞬間」はbehaviors側(`src/scene/elephant/behaviors/breakBranch.ts`、編集禁止)を
見ると鼻を伸ばす1.6s+2〜3回引く動作(各1.1s)の後、概ね3.8〜4.9秒付近で折れる。behaviors側は変更
できない契約のため、`behavior:start`受信から2.8秒後にbranch-snapを再生するタイマーで近似し、
それより早く`behavior:complete`が届いた場合はその時点でタイマーを取り消して即座にbranch-snapを
鳴らす(二重再生はしない)設計にした。

### unlock/ambience/ui-tapの配線(`src/main.ts`)

- `document`への`pointerdown`/`touchstart`(各`{once:true}`)1本ずつで`audioSystem.api.unlock()`+
  `startAmbience()`を呼び、初回のみ`audio:unlocked`をemitする(`unlock()`/`startAmbience()`自体は
  内部で冪等なので二重発火しても問題ない)。
- `bindUiTapSounds(audio)`が`document`に1本の`pointerdown`委譲リスナーを張り、`button`/
  `[role="button"]`にマッチする要素へのタップだけ`ui-tap`を鳴らす(食材トレイのドラッグでは鳴らない)。
- unlockリスナーを先に`document`へ登録してからui-tap委譲を登録しているため、同一tapイベントの
  バブリング順で「unlock→ui-tap」の順が保証される(初回タップからui-tapが鳴る)。

## 2. 保存(`src/save/save.ts`)

`SaveData`契約(docs/INTERFACES.md)どおり。`loadSave()`はJSON.parse失敗・非object・欠損キー・
型不一致(observedBehaviorsの不正値/quality不正値/ambienceVolumeの範囲外)いずれでも
throwせず既定値(または既定値のうち該当フィールドのみ)へ復旧する。`updateSave(patch)`が
部分更新API(トップレベルは上書き、`settings`はキー単位でマージ)。`resetSave()`が既定値へ
上書き保存する。`src/game/album.ts`はS4の仮実装(localStorage直書き)をこれへ完全に置換し、
`loadSave`/`persistSave`/`defaultSaveData`/`SAVE_KEY`/`updateSave`を再エクスポートして
既存の呼び出し元(`app.ts`/`screens/*`/既存テスト)を無改造で維持した。

## 3. せってい画面(`src/ui/settings.ts` + `infoPanel.ts`統合)

タイトル画面の「i」→じょうほうパネル→「せってい」ボタンで開く(タップでじょうほうパネルは
閉じてから、せっていパネルを開く二重表示防止済み)。全操作64px以上のタッチ対象:
- **おと**: ON/OFFの大きなトグル(76×44pxの見た目+`::after`で±10pxのヒット領域拡張=実質64px超)。
- **かんきょうおん**: 0〜100%スライダー(5%刻み、つまみ44px)、数値表示付き。
- **うごきをへらす**: トグル。
- **ひかりをよわく**: トグル(`world.setLightDim`、下記参照)。
- **がしつ**: low/medium/high/autoの4択セグメントボタン(各min-height 64px)。
- **データをリセット**: タップで即消去せず、確認ブロックへ切り替わる二段階
  (「けす」/「やめる」、各big-btn 64px)。
すべて`ctx.applySettings(patch)`(`src/ui/app.ts`)を経由して即時反映+`persistSave`保存する。

### `applySettings`の実装(`src/ui/app.ts`)

1箇所に集約し、各設定に応じて副作用を実行する:
- `reducedMotion`: OSの`prefers-reduced-motion`とのOR条件を再計算し(`applyReducedMotion()`)、
  `world.setReducedMotion`/`cameraRig.setReducedMotion`へ反映+`<html>`へ`reduced-motion`クラスを
  付け外し(styles.cssの`:root.reduced-motion`セレクタがOSメディアクエリと同じ短縮を適用)。
  OS設定自体が変化した場合も`matchMedia`の`change`イベントで追従する。
- `dimLight`: `world.setLightDim(on)` → `lighting.ts`の`setDim()`が光強度を約70%に(hemi/sun/ambient
  いずれも、`setTimeOfDay`後も維持されるよう`applyIntensities()`へ集約した)。
- `muted`/`ambienceVolume`: `AudioApi.setMuted`/`setAmbienceVolume`へ委譲。
- `quality`: "auto"以外なら`renderer.setQuality`+`world.setQuality`を実行するブリッジ
  (`applyQuality`、main.tsから注入)。"auto"は既定の"medium"へフォールバックする(自動検出ロジックは
  未実装、既定へ戻すのみ)。
- `resetSaveData()`: `resetSave()`で保存を既定値へ戻し、`window.location.reload()`で全状態
  (セッション/アルバム/音声/画質)を素朴に作り直す。

### `world.setLightDim`(最小追加)

`src/scene/world.ts`に`setLightDim(on)`を追加(`WorldApi`本体ではなく`World`拡張、既存の
`setReducedMotion`と同じ立ち位置)。`src/scene/environment/lighting.ts`の`LightingRig`に
`setDim(on)`を追加し、hemi/sun/ambientの強度を`TIME_CONFIGS`の基準値×(dimmed?0.7:1)で
常に再計算するよう`applyIntensities()`へ集約した(`setTimeOfDay`を後から呼んでも暗さの設定が
失われない)。

## 4. reduced-motion(OS ∪ 設定)

`src/ui/app.ts`の`applyReducedMotion()`が`window.matchMedia("(prefers-reduced-motion: reduce)")`
(jsdomでは`matchMedia`が無いためガード済み)と`save.settings.reducedMotion`のORを毎回計算し、
world/cameraRig/`<html>`クラスへ反映する。`styles.css`は既存の`@media (prefers-reduced-motion:
reduce)`ブロックと全く同じセレクタ・値を持つ`:root.reduced-motion`版を追加し、設定側トグルだけが
ONの場合でもUIアニメ(big-btn/food-tray/finish-gesture/gate-lever/seek-pop-card/album-card/
hint-bubble)が同じだけ短縮される。ヒントの微振動が光のみになる仕様は`world.ts`の`highlightSpot`
既存実装(`reducedMotion`時はanchor位置固定+light.intensity固定)がそのままOS∪設定の結果を
受け取るため、追加変更なしで満たされる。

## 5. PWA(`vite.config.ts` / `index.html` / `public/` / `scripts/gen-icons.mjs`)

- `manifest`: name「ゾウのかくれごはん」、short_name「ぞうのかくれごはん」、
  theme_color/background_color `#fff8ef`、display `standalone`、orientation `any`、
  icons 192/512(+512をmaskableとしても登録)。
- アイコンは`scripts/gen-icons.mjs`でローカル生成しコミット済み(`public/icons/icon-192.png`,
  `icon-512.png`, `apple-touch-icon.png`)。**npm依存を追加せず**、Node組み込みの`zlib.deflateSync`
  だけで手書きのPNGエンコーダ(IHDR/IDAT/IEND手組み+CRC32実装)を書き、暖色パレット
  (`#fff8ef`背景/`#ffc9c0`バッジ/耳`#c9a79c`/頭`#d8c3b4`/ほっぺ`#ff8a70`)のゾウの顔アイコンを
  ピクセル単位のアルファブレンド描画で作った(外部画像・CDN不使用)。
- `favicon.svg`(`public/`直下)を追加し、`index.html`の`<link rel="icon" type="image/svg+xml">`で
  参照(以前は未設定で404が出ていた事象を解消)。`apple-touch-icon`も追加。
- `index.html`に`apple-mobile-web-app-capable`/`mobile-web-app-capable`/
  `apple-mobile-web-app-status-bar-style`/`apple-mobile-web-app-title`/`description`を追加。
- `workbox.globPatterns`をjs/css/html/svg/png/ico/webmanifest/jsonへ広げ、`navigateFallback:
  "index.html"`、`cleanupOutdatedCaches`/`clientsClaim`/`skipWaiting`を有効化。
  `registerType: "autoUpdate"`のまま(新SWが即有効化される)。
- SW登録自体は`src/main.ts`が`virtual:pwa-register`(vite-plugin-pwaの仮想モジュール、型は
  `src/vite-env.d.ts`で最小限を宣言)経由で手動実行するよう新規実装した(S4時点では
  `?nosw=1`のconsole.warnのみで、通常起動時も登録されていなかった)。`?nosw=1`のときは
  `registerSW()`自体を呼ばずスキップする(既存契約どおり)。

## 7. アクセシビリティ

- 全ボタンに日本語aria-label。`createBigButton`は`ariaLabel`省略時に表示ラベル(ひらがな)を
  そのまま`aria-label`へ使うようにしたため、既存の全画面のbig-btnが個別変更なしでaria-label持ちに
  なった。それ以外(info-fab/album-home-btn/gate-lever-handle/food-tray__slot/settings系)は
  個別に日本語aria-labelを付与済み。
- `:focus-visible`のグローバルスタイルを追加(マウス操作時はアウトラインなし、キーボード操作時
  のみ太いアウトライン)。円形ボタン(info-fab等)は`border-radius:50%`のアウトラインに調整。
- **キーボードQAフォールバック**(確認の上、無かったため追加):
  - 食材トレイの各スロット(`food-tray__slot`)に`tabindex="0"`+`keydown`(Enter/Space)を追加し、
    ドラッグの代わりに残っているスポットへ即座に自動配置する(`hide.ts`の`autoPlaceKeyboard`、
    タスク指示「hide操作はEnterで自動配置でよい」のとおり仕上げスワイプも省略)。
  - ゲートのレバー(`gate-lever-handle`)にも`tabindex="0"`+`keydown`(Enter/Space)を追加し、
    スワイプの代わりに即座に`triggerOpen()`する。
  - タイトル/アルバム/せってい/じょうほうの各ボタンは元々`<button>`要素のため、Tab+Enterは
    ブラウザ標準動作でそのまま機能する。
  - これでtitle→hide(Tab+Enterで食材を配置)→gate(Tab+Enterで開ける)→seek(操作不要、自動進行)
    →album(Tab+Enterで次プレイ)まで、マウス/タッチ無しのTab+Enterだけで一周できる。
- 高速点滅: 新規追加した点滅/明滅アニメーションはない(トグルのtransformアニメのみ、0.15秒の
  スライド)。既存のhint-bubble/gate-lever-handleの明滅もS4から変更なし(1秒未満のbrightness変化、
  3Hz未満)。

## 11. 実機音出し未確認(明記事項)

このタスクの検証環境ではブラウザの音声出力を人手で聴取できないため、11種のSfx+ambienceの
実際の音質・音量バランス・ミックス感は**実機/ブラウザでの聴取確認をしていない**。担保しているのは
以下のみ:
- `tests/unit/audio-mapping.test.ts`によるイベント→SfxIdマッピングの網羅的なユニットテスト
  (AudioContextモック無し、フェイクSfxで呼び出し引数のみ検証)。
- 実装レビュー(本レポート「1. 音」節の音色設計表、WebAudioノード構成の目視確認)。
- `engine.ts`/`sfx.ts`/`ambience.ts`はいずれも「ctx/masterGainが無ければ無音で早期returnし、
  例外はcatchして握りつぶす」設計のため、jsdom環境(AudioContext非対応)でも例外を投げず、
  既存のUI/統合テスト実行時に音声関連のエラーは一切出ていないことは確認済み(`npm run test`の
  出力に音声関連のスタックトレースは無い)。

実機での音出し確認(iOS Safari実機でのunlock挙動含む)は本タスクのスコープ外として、担当外の
チームまたは次工程での確認を推奨する。

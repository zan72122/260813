# S3 レポート — ゾウ本体(モデル/trunk/歩行/idle/登場探索)

## 作ったもの(すべて `src/scene/elephant/` 内、外部モデル/画像テクスチャ不使用)

- `proc.ts`: ゾウ専用のジオメトリ変形ヘルパー(`environment/proc.ts`は参照のみ・編集不可のため補完する形で新設)。
  `addTwinDomeBumps`(頭頂の膨らみ2つをsmoothstepバンプで追加)、`addBackArch`(上半分のみにアーチ)、
  `flattenBelly`(下半分を平らに)、`paintTwoToneByLocalZ`(耳の内側/外側の頂点色分け)、
  `paintGradientAlongY`(鼻の根本→先端の頂点色グラデーション)、`paintUniform`。
- `model.ts`: `buildElephantModel(rng: Rng): ElephantModel`。
- `trunk.ts`: `class Trunk`(鼻)。
- `gait.ts`: `class Gait`(歩行)+ 純計算のexport関数(`advanceToward`, `legAngles`)。
- `elephant.ts`: `class Elephant`(統合クラス)。
- `index.ts`: 上記の再export。

## モデル構造(model.ts)

- 胴体: `THREE.LatheGeometry`(profile 9点×28分割)を`rotateX(90°)`して体長方向をZ軸にし、
  `addBackArch`(上半分にアーチ)+`flattenBelly`(下半分平ら)で変形。角張ったprimitiveの寄せ集めではなく、
  1枚のLatheメッシュを変形したなめらかな輪郭。`roughenGeometry`で微小な表面ノイズ、`paintVertexAO`で
  肌色`#8d8681`のムラ(頂点色)。
- 頭部: `THREE.SphereGeometry`を非一様scaleし、`addTwinDomeBumps`で頭頂に2つの膨らみ(twin domes)。
- 耳: `THREE.IcosahedronGeometry`を扁平scale(小さめ・丸い)、`paintTwoToneByLocalZ`で内側に桃色
  `#c9a8a0`、外側は肌色。左右に`pivot`(耳の扇ぎ用)。
- 目: 小さな黒目球(`#241d18`)+ まぶた(球の一部キャップ、常時軽く伏せた「下がり目」の休止角度から
  数秒毎に瞬き)。
- 脚: 4本、各々`hip`(股関節ピボット、前後スイング)→`knee`(副ピボット、僅かな持ち上げ)→
  脚メッシュ(シン+フット+爪3個を`mergeGeometries`で1メッシュ化、頂点色で足先を暗く/爪をクリーム色に)。
- 尻尾: `TubeGeometry`+先端の房(`IcosahedronGeometry`暗色)を`mergeGeometries`。
  根本のpivotで常時ゆらゆら(reducedMotion時は最小化)。
- **肩高の正規化**: 胴体geometryの実測bboxの高さ(脚長+胴体の縦幅)から`SHOULDER_HEIGHT(2.6)`に
  正確に一致するスケール係数を逆算し、`buildGroup.scale.setScalar(modelScale)`で全パーツへ一括適用。
  手計算の勘に頼らずbboxで保証しているので、profileの数値を今後調整しても肩高は常に2.6に収まる。
- **常時アニメ**(`model.update(dt)`): 呼吸(胴体スケール微振動)、耳の扇ぎ(常時、seed毎に位相差)、
  まぶたの瞬き(数秒毎、`Rng`で間隔をジッター)、尻尾のゆらぎ。`setReducedMotion(on)`で振幅を最小化
  (瞬き間隔も伸ばす)。`setWalking(on)`で耳/尻尾の揺れが少し大きくなる(歩行中は元気に動く)。
- **三角形予算**: `tests/unit/elephant.test.ts`の`keeps the elephant's total triangle budget under
  ~25k`で実測(trunk込みで実測値は数千〜1万程度、予算内)。

## trunk.ts(S3b向け詳細)

- ジオメトリ: 付け根半径`TRUNK_ROOT_RADIUS=0.34`→先端`TRUNK_TIP_RADIUS=0.13`にテーパーした
  カスタムチューブ(`RADIAL_SEGMENTS=8` × `RINGS_PER_BONE * TRUNK_BONE_COUNT`のリング)。
  `TRUNK_BONE_COUNT=9`本のボーン(要件8-10本の範囲)へ2ボーン線形ブレンドのskinIndex/skinWeightで
  スキニング(`tallTree.ts`の2ボーン枝と同じ手法を9ボーンへ拡張)。頂点色は根本の肌色から先端72%地点
  以降で桃色`#c9a8a0`へブレンド(`paintGradientAlongY`)。先端には「指」として小さな扁平球
  (アジアゾウは1本、桃色)を最終ボーンの子として追加。
- **制御API**:
  - `setTarget(worldPos: THREE.Vector3, opts？: { curl？: number; instant？: boolean })`:
    鼻先の目標をワールド座標で指定。`opts.curl`(0..1)で同時に巻き込み量も設定可。`instant`で
    平滑化をスキップして即座にその姿勢へ(QA/テスト向け)。
  - `setCurl(v: number)`: 巻き込み量だけを独立に設定。
  - `setSwing(amount: number)`: 歩行中のスイング強さ(0..1)。elephant.tsが`gait.isMoving`から設定。
  - `setReducedMotion(on: boolean)`
  - `relax()`: 明示的な目標を解除し、自然な垂れ下がり(根本ローカル`(0, -TRUNK_LENGTH*0.9,
    TRUNK_LENGTH*0.24)`、やや前方に垂れる)へ戻る。
  - `update(dt: number)`: 毎フレーム呼ぶ(elephant.tsが内部で呼んでいる。S3b側で`Trunk`を
    直接生成する場合は呼び出しが必要)。
  - `getTipPosition(): THREE.Vector3`: **現在の鼻先ワールド座標**。
- **spline計算**: 根本(ローカル原点)→目標(1次遅れ後の`currentTip`)の間に、重力たわみ(下方向
  オフセット、静止時ほど大きい)+`Rng`由来のseedノイズ揺らぎ(sin/cos、個体ごとに位相が違う)+
  歩行中スイングを加えた2つの中間制御点を作り、`THREE.CatmullRomCurve3`で全長をサンプリング。
  各ボーンの絶対姿勢は「静止姿勢の軸(0,1,0)からサンプル間方向への回転」を`Quaternion.
  setFromUnitVectors`で求め、親ボーンとの相対回転(aim-chain FK)をボーンへ適用。`curl`は
  最後の2ボーンへ追加のX軸回転を加算する。
  - **1次遅れ(重さの表現)**: `setTarget`の目標(`targetLocal`)へ`currentTip`が
    `1-exp(-lagK*dt)`で指数的に追従する(通常`lagK=3.0`、reducedMotion時`5.5`=速め)。
  - **既知の制限**: ボーンは固定長(合計`TRUNK_LENGTH`)で駆動する見た目用のFK近似のため、
    目標が根本から遠い/近いによって視覚上の鼻先が目標を多少行き過ぎる/届かないことがある
    (現実の鼻も伸縮しないので不自然ではないが、ピクセル単位では一致しない)。**そのため
    `getTipPosition()`はFK近似ではなく、1次遅れ後の権威ある目標座標(`currentTip`をワールド
    変換したもの)を返す設計にした。** ゲームロジック(S3bの`probe-gap`/`reach-pipe`等の判定)は
    `getTipPosition()`を「今どこまで鼻が届いているか」の正として使ってよい。見た目のボーン
    位置とはわずかにズレうるが、判定用途では`getTipPosition()`の方を信頼すること。

## gait.ts

- `class Gait`: `walkTo(points: Vec3Like[]): Promise<void>`。waypointを順に辿り、向きは
  最短角補間(`angleLerp`)で滑らかに追従。`stop()`で現在の待機を即resolveして打ち切り。
- 脚アニメ: `legAngles(phase, phaseOffset, moveFactor)`(純関数、export済み)。4本脚は
  `phaseOffset`で対角パターン(前左・後右が同位相、前右・後左が逆位相)。
- 体の上下動+ロール: `bodyPixot.position.y`/`rotation.z`をsineで微振動(`isMoving`時のみ、
  reducedMotion時は0)。
- 歩行速度: `speed`既定`1.2`(ワールド単位/秒、ゆったり)。
- 接地: 毎フレーム`groundHeight(x,z)`(`environment/terrain.ts`からimport、参照のみで編集なし)+
  `groundOffset`(脚長×モデルスケール)をroot.position.yへ反映。埋まり/浮きは出ない
  (`groundHeight`の起伏±0.22程度に追従)。
- `advanceToward`/`legAngles`はthree.js非依存の純計算(`Vec3Like`のみ)としてexportしており、
  jsdom/Node双方で軽量にテスト可能。

## elephant.ts(統合クラス、WorldApi接続用)

- `constructor(rng: Rng)`: `rng.fork("elephant-model")`をmodel.tsへ、`rng.fork("trunk")`を
  trunk.tsへ渡す。嗅ぎ時間・初動方向・鼻ノイズ位相は`rng`由来(`elephant.test.ts`は同一seedでの
  再現性は明示テストしていないが、`Rng`はmulberry32決定論的実装なので同一seedなら同一挙動)。
- `readonly trunk: Trunk`: S3b(behaviors)が直接アクセスして`setTarget`/`relax`/`getTipPosition`/
  `setCurl`を呼べる。
- `update(dt)`: 非表示中(`enter()`未呼び出し)は何もしない。表示中は`gait.update`→
  `model.setWalking`→`model.update`→(timedTasksを`trunk.update`より先に進めて同フレーム反映)→
  `trunk.update`の順。
- `enter(): Promise<void>`: ゲート外側(`x≈0±0.5, z=-14.4`、`terrain.ts`の`isGateArc`基準z=-12.6の
  外側)から場内(`z≈-9.4`付近)へ2waypointで歩き、鼻を高く(地面基準+1.55、reach 0.75)上げて
  2-3秒(`rng.range(2,3)`)左右に探る(`sniffAround`とは別の高さ設定=`trunkSearchSweep`を共有)。
  完了で`idle`状態へ。
- `walkToSpot(spotId: SpotKind): Promise<void>`: `SPOTS`の`approach`へ歩く。
- `sniffAround(seconds): Promise<void>`: その場で鼻を**低く**(地面基準+0.32)左右に振って嗅ぐ。
  `enter()`の「鼻を上げて探す」より低い高さ設定を使う(仕様の使い分け通り)。
- `idleAt(pos: Vec3 | null)`: `pos`指定時は`gait.snapTo`で即座にその位置へ(向きは現状維持)。
  呼吸/耳/瞬き/尻尾は`update(dt)`が継続する限り常時再生。
- `getState()`: `"hidden"|"idle"|"walking"|"sniffing"|"entering"`。
- `setReducedMotion(on)`: model/gait/trunk全てへ伝播。

## world.tsへの接続(フック登録のみ、要件通り)

- `createWorld(opts?: { ...; seed？: number })`に`seed`を追加(既定1)。
  `createRng(seed).fork("elephant")`で`Elephant`を構築し`scene.add(elephant.object3D)`
  (コンストラクタで`visible=false`、`enter()`まで非表示)。
- `registerHooks({ elephantEnter: () => elephant.enter(), elephantIdleAt: (pos) =>
  elephant.idleAt(pos) })`をworld構築時に自動登録。**`elephantSeek`は登録していない**
  (S3bが接続する契約通り、未登録のままフォールバックwarn+即resolveが効く)。
- `update(dt)`で`elephant.update(dt)`を呼ぶ。`setReducedMotion(on)`で
  `elephant.setReducedMotion(on)`を伝播(コンストラクタ直後にも初期`reducedMotion`を反映)。
  `dispose()`で`elephant.dispose()`。
- **デバッグアクセサ**: `debug/qa.ts`(編集禁止)にelephant固有の配線は無いため、`World`
  インターフェースへ`getDebugInfo(): { elephant: { present: true; visible; state; position } }`
  を追加した(小さなアクセサ、要件通り)。`getState()`配線自体は`main.ts`(S1所有、編集禁止)が
  `debugApi.registerHandlers({ getState: ... })`する際に`world.getDebugInfo()`をマージすれば
  `'elephant'`キーが載る。**この配線自体はS3の担当範囲外(main.ts編集禁止)のため未接続**。
  S4等で`getState: () => ({ ...world.getDebugInfo(), phase, session, ... })`のように合成する
  想定。
- **QA視覚確認用の一時的な足場**(`world.ts`内、`?qa=1`時のみ発火): ゾウを`visible=true`にして
  `idleAt({x:0,y:0,z:2})`へ配置し、`window.__elephantDebug`に`Elephant`インスタンスを生やす
  (playwright等から`.enter()`/`.walkToSpot()`/`.sniffAround()`を直接呼んでQA撮影できるようにする
  ためだけの足場)。本番フロー(`qa`未指定)では一切発火しない。

## 既存テストへの影響(重要な仕様上の変更)

`tests/unit/world.test.ts`の「no hook registered」テストは、S2時点では`elephantEnter`も
フォールバック(warn+即resolve)される前提だったが、S3の要件により`elephantEnter`/
`elephantIdleAt`はデフォルトで実装が接続されるべきものになった(`elephantSeek`のみ未接続のまま)。
これに伴い該当テストを最小限だけ更新した:
- `elephantSeek`は引き続き未登録→フォールバックwarn+即resolveであることを確認。
- `elephantEnter`は実際に歩行+匂い探索アニメーションを再生するようになったため、
  `world.update(dt)`を積んで進める形に変更し、実際に解決することを確認。
既存の他77+13件のテストは無変更。

## 既知の制限

1. trunkのFK(ボーン姿勢)は近似であり、`getTipPosition()`は権威あるスムージング後の目標座標を
   返す設計にした(上記「既知の制限」参照)。見た目のボーン先端と数ピクセル単位ではズレうる。
2. `Gait`は同時に1つの`walkTo`タスクしか保持しない。新しい`walkTo`/`walkToSpot`を呼ぶと前の
   Promiseは(resolveされないまま)差し替えられる。呼び出し側(S3b/S4)は前の移動の完了を
   `await`してから次を呼ぶこと。
3. 脚は「股関節ピボット+副ピボットの回転」による簡易gait(スプライン/IKソルバ不使用、要件通り)。
   個々の足がIKで地形の凹凸に正確に沿うわけではなく、体全体のYを`groundHeight`に追従させる
   簡略化(起伏が緩やかなので破綻はしない)。
4. `getDebugInfo()`を`window.__ELEPHANT_GAME_DEBUG__.getState()`へ実際にマージする配線は
   `main.ts`編集禁止のため未実施(次工程で`world.getDebugInfo()`を使うだけでよい)。
5. QA用の`window.__elephantDebug`足場は`?qa=1`時のみの一時的なデバッグ足場であり、正式な
   ゲームAPIではない(正式には`WorldHooks`経由)。

## 発見バグ(詳細は`docs/QA_REPORT.md`の「3. 発見バグ」節)

1. **[修正済み]** QA用ゾウのdebug配置がタイトル/隠し/アルバム画面のスクショに写り込む
   (`src/scene/world.ts`、S6編集許可範囲内のため修正)。
2. **[範囲外・記録のみ]** `jumpTo("seek")`(`?act=seek`)が`elephantEnter()`の歩行tweenと
   seek画面自身の`elephantSeek`ループの`gait.walkTo`競合により永久にstallする。原因は
   `src/ui/app.ts`の`prepareForPhase`が`elephantEnter()`を`await`せず発火のみでseek画面をmount
   する設計(`ops/reports/S4.md`に「発火のみ」と明記された既存仕様)。**実際のゲートUI操作
   (`triggerOpen()`)では`elephantEnter()`を`await`しているため発生しない**、QA専用ショートカット
   のみの問題。再現手順・原因調査はQA_REPORT.mdに記載。E2E側は`act=seek`を使わない設計で回避した
   (`screenshots.spec.ts`は`act=gate`+手動`openGate/elephantEnter` await、`full-loop.spec.ts`は
   実際のgate UIスワイプ経由、`behaviors.spec.ts`は`playBehaviorDirect`直接呼び出し)。
3. **[範囲外・記録のみ]** `DebugApi.screenshotReady()`が`docs/INTERFACES.md`の契約
   (「カメラ遷移・tween静止でtrue」)どおりに機能せず、`src/main.ts`(編集範囲外)が
   `() => true`固定スタブを登録している。E2E側は`installCameraStabilityTracker`/
   `waitForCameraSettled`(カメラ位置の連続フレーム比較)で代替した。
4. **[範囲外・記録のみ]** `getState()`へ`renderer.info`(draw calls/triangles)を含める配線が
   できなかった。`GameRenderer`インスタンスと`getState()`ハンドラ登録は共に`src/main.ts`
   (編集範囲外)にあるため。代替として`window.__worldDebug.scene`をJS側で走査した概算三角形数
   (18,210、メッシュ数69、quality=low時点)をQA_REPORT.mdに記録した。

## 不安定だったテストへの対処(方針転換の記録)

初回実行時(バックグラウンド実行がコンテナ都合で中断された影響もあり)、以下4件が失敗した。
いずれも「待ち方の設計不備」が原因で、retryで誤魔化さずロジック側を修正した:

1. `smoke.spec.ts`(4project全て失敗): `getState().ready`を検証していたが、`main.ts`が登録する
   `getState()`ハンドラは`ready`フィールドを含まない独自オブジェクトを返す設計だった
   (`ready`はDebugApiのトップレベルpropertyであり、`getState()`の中身ではない)。
   `window.__ELEPHANT_GAME_DEBUG__.ready`を直接見るよう修正。
2. `full-loop.spec.ts`: `timeScale=8`下では`intro`フェーズのtweenが数十msで自己完結し、
   `waitForPhase(page,"intro")`(30秒待ち)が確実に捕捉できるとは限らないことが判明。
   2秒の短いタイムアウトで「捕捉できれば実タップでスキップ、できなければそのまま`hide`到達を待つ」
   よう設計変更した(方針転換: フェーズ捕捉に依存しない進行に変更)。
3. `behaviors.spec.ts`: `album.session`への記録は`src/ui/screens/seek.ts`のUI層イベント購読が
   行うため、seek画面を経由しない`playBehaviorDirect`単体呼び出しでは更新されないことが判明
   (仕様どおりの挙動)。`world.events`経由の`behavior:complete`発火を正としてassertするよう修正。
4. `screenshots.spec.ts`(2回失敗、2回目の失敗内容を見て方針転換): 1回目は`act=seek`ジャンプが
   バグ2.(上記)によりstallし30秒timeout。`act=gate`+手動`openGate/elephantEnter`awaitへ変更。
   2回目はループ内で`void playBehaviorDirect(...)`(fire-and-forget)にした結果、次のイテレーションの
   `page.goto()`がそのPromiseを「Execution context was destroyed」で後からrejectし、未処理rejection
   としてテストランナーが後続の`waitForTimeout`を巻き込んで異常終了させていた。
   `.catch(() => {})`で明示的に握りつぶすよう修正、以降安定した。
   さらに目視確認で`04-dig-sand.png`にタイトル画面の大きなUI(「あそぶ」ボタン等)が3D演出へ重なって
   写り込んでいることに気づき(playBehaviorDirectがFSMのphaseを変えないため)、`#ui-root`を撮影直前
   に一時的に非表示化する`hideUiOverlay`ヘルパーを追加して解消した(`src/scene/cameras.ts`のS3b既存
   撮影手順と同じ考え方)。

最終的に`npm run qa:e2e`/`npm run qa:screenshots`とも**retry無しで安定green**であることを2回連続
(それぞれ単体実行+全spec通し実行)で確認した。

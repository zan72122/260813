# DECISIONS — 設計判断記録

| # | 判断 | 理由 |
|---|---|---|
| D1 | React不使用。DOMオーバーレイUI＋Three.js | 4歳児UIは画面数が少なく、DOM直書きの方が軽量・safe-area/アクセシビリティ対応が容易。バンドル削減 |
| D2 | WebGPU不採用、WebGL2のみ | iOS SafariのWebGPUは世代差が大きく、看板動作の安定性を優先。three.jsのWebGLRendererで十分 |
| D3 | 物理エンジンなし。tween+procedural skeletal | 因果は決定論で十分。deterministic＝seed再現性・テスト容易性・低負荷 |
| D4 | 鼻はIKでなくスプライン追従bone chain | CCD/FABRIKより「重さ・遅れ・しなり」の演出制御が直接的で、破綻姿勢が出ない |
| D5 | 全アセットをコード生成（プロシージャル） | 著作権リスクゼロ、バンドル小、seedによる微差生成と相性が良い |
| D6 | 音は全てWebAudio合成 | 外部音源のライセンス問題を根絶。短い操作同期音は合成が向く |
| D7 | スポットは各kind 1個、behaviorと1:1 | 4歳児の認知負荷を下げ、5行動の差別化を最大化。ガイドは3スポットで3系統の操作差を体験 |
| D8 | ガイド初回は stone-gap / sand / high-branch | 押し込む・かぶせる・引き上げるの3操作系統を初回で網羅。pipe/banyanは再プレイ動機に残す |
| D9 | 状態機械は自作の小さなFSM | XState等は過剰。遷移表+リスナーで十分、不正遷移は無視(連打耐性) |
| D10 | vite-plugin-pwa (generateSW, autoUpdate) | precacheマニフェスト自動生成で新旧バンドル混在を防ぐ。手書きSWは更新事故リスク |
| D11 | UIテキストは最小限のひらがな＋絵優先 | 文章非依存の進行。ラベルは読み聞かせ用の添え物 |
| D12 | アルバムは端末内蓄積(observedBehaviors) | 5行動×1回3スポット→未見行動が再プレイ動機になる。ノルマ表示はせず絵が増えるだけ |
| D13 | E2Eは ?qa=1 + debug API 待機で駆動 | SwiftShaderの低FPS対策。timeScale=8/16とjumpToで実時間を圧縮 |
| D14 | Playwrightはプリインストールchromiumを使用 | 環境指針に従い再ダウンロードしない |
| D15 | 座標系: 放飼場中心が原点、手前(+Z)が観察デッキ | カメラ設計とスポット配置の共通基準 |
| D16 | intro/題名画面もthree.jsの実シーンを背景に使う | 別アートを作らず品質を集中。ロード完了が視覚的に分かる |
| D17 | 品質autoは DPR・UA・初回フレーム時間で推定 | ヘッドレス/低速機はlowへ。ユーザー設定が常に優先 |
| D18 | 砂かぶせは左右スワイプ2回以上で完了 | 「指を動かした感覚」を残しつつ失敗なし。1タップ自動完了にしない |

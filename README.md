# あまいひみつ

4歳児向け iPhone / iPad モバイル Web ゲーム。
**最後の最後まで「作っているものの正体」を隠す**プリン工房です。

遊ぶ側は「何だろう、この茶色い液体と黄色い液体」から始まり、
型を持ち上げた瞬間に初めて「プリンだ！」に到達します。

```
npm start          # http://localhost:4173 で配信
npm test           # Chromium で 1 周プレイして検証（縦画面）
npm run test:land  # 同上（横画面）
npm run test:hero  # 「型を抜く 3 秒」だけをコマ撮り
```

Playwright がグローバル導入の環境では `NODE_PATH=/opt/node22/lib/node_modules` を付けてください。
ビルド手順はありません。静的ファイルをそのまま配信すれば動きます。

## 認知体験の設計

| # | 工程 | 動詞 | 操作 | 視覚変化 |
|---|------|------|------|----------|
| 1 | `caramelize` | あたためる | 大きなレバーを下へドラッグ | 透明な砂糖液 → 淡い金 → 琥珀色 |
| 2 | `pour-caramel` | そそぐ | 鍋を傾けるドラッグ | 型の底に琥珀の層がたまる |
| 3 | `mix` | まぜる | 円運動 | 白い筋が消えてなめらかな黄色に |
| 4 | `pour-custard` | そそぐ | ボウルを傾けるドラッグ | 茶色の上に黄色が重なり二層になる |
| 5 | `steam` | あたためる | 蓋を下へドラッグ | 湯気が噴き、液面が固まる |
| 6 | `chill` | ひやす | 冷たい扉を横へドラッグ | 全体が青くなり霜がつく |
| 7 | `plate-on` | かぶせる | 皿を下へドラッグ | 白い皿が型にかぶさる（なぜ？） |
| 8 | `flip` | ひっくりかえす | 大きな弧のスワイプ | 皿と型が一緒に 180 度回る |
| 9-11 | `demold` | かたをぬく | ゆっくり上へドラッグ | 型が上がる → ぷるん → カラメルが流れる |
| 12 | `reveal` | ―（自動） | ― | カメラが引いて全体が見える |

工程 9・10・11 は「1 つの操作から連続して起きる 1 つの体験」なので
1 モジュール（`demold`）にまとめ、その内部を
**引き上げ → 離型 → 減衰振動 → カラメル流下**の 4 拍で構成しています。

### 正体を隠す仕掛け

- ゲーム中に**文字は一切描画しません**（`fillText` を 1 度も呼びません）。
  誘導は「手のアイコン」と「破線の道すじ」だけです。
- タイトル画面に出るのは、鍋・銀色の型・ボウルの 3 つだけ。
  完成品・シルエット・パッケージは登場しません。
- ブラウザのタブに出るタイトルも「あまいひみつ」で、正体を明かしません。
- 型は不透明な銀色なので、工程 1〜8 では中身の形が一切見えません。
- 黄色い塊としての姿が初めて現れるのは工程 9（全 10 モジュール中 9 番目 ≒ **85% 地点**）。
  それも下から少しずつで、全体像が見えるのは工程 11〜12 です。

### リプレイ磁石（最優先で磨いた 3 秒）

「型を持ち上げる直前 → 外れる → ぷるん → カラメルが流れる」に予算を集中しています。

- 引き上げの終盤は**わざと抵抗**を作り、プリンがわずかに伸びる（`stick`）。
- しきい値を越えると離型。カメラが軽く揺れ、`purun` 音が鳴る。
- ばね（ζ≈0.4 の減衰振動）で**つぶれて戻る**（`squash`）。
- 進行波の頂点オフセットで**横に揺れる**（`wobble`、上ほど大きい）。
- 揺れが収まりはじめる頃にカラメルが頂上から側面へ**遅れて流れ落ちる**。

完成画面には大きな「もう一度型をぬく」ボタンがあり、
押すと**型がプリンにかぶさりながら降りてきて**、すぐにもう一度引き抜けます。

## 4歳児向けの入力設計

- **画面のどこを触っても操作できます。** 対象物を正確にタップする必要はありません。
  これが「指がプリンやカラメルを隠さない」ための一番強い対策でもあります。
- **進捗は減りません。** 逆方向の手ぶれや往復は無視され、正しい向きの成分だけが加算されます。
- **斜めでも通ります。** 直交成分も 12% だけ加点されます。
- **円運動は指の移動平均を中心に判定します。** 画面のどこで、どんな大きさで回しても成立し、
  ぐるぐる回せなくても「ゴシゴシ往復」で進みます。
- **反転は 78% まで回せば自動で決まります。**
- **必要なドラッグ量は画面サイズから計算します**（`vDist` / `hDist`）。
  iPhone 縦でも iPad 横でも「大きく 1〜1.5 ストローク」で完了します。
- **16 秒（型抜きは 26 秒）触られないと自動で進みます。** 詰まって泣くことはありません。
- 制限時間・採点・ゲームオーバー・失敗はありません。

## 技術的な選択

### WebGL2 ハイブリッド（Hero だけシェーダ、それ以外は Canvas2D）

画面は 3 枚重ねです。

| 層 | 技術 | 描くもの |
|---|---|---|
| `#back` | Canvas2D | 背景・作業台・Hero より奥の小物。被写界深度の CSS ぼかしを掛ける |
| `#gl` | **WebGL2** | プリン・カラメル・銀の型・皿・鍋・ボウル・液体・注ぐ流れ |
| `#front` | Canvas2D | Hero より手前の小物（蓋・冷蔵扉・炎・湯気）と、文字なし UI |

塗る面積の 2〜3 割だけをシェーダに通すので、質を上げつつ負荷を抑えられます。
**WebGL2 が無い端末では自動的に旧来の Canvas2D 経路（`fallback`）に落ちて、
絵は簡素になりますが遊べなくなることはありません。**

2D と WebGL の投影は**同じ式**から作ってあります（`View.updateProj`）。
既存の擬似 3D は「仰角 θ の正射影」そのものだったので、`sinθ = view.k` として
正確な正射影行列を組み立てれば、2 つの層はピクセル単位で一致します。

### 質感の 4 本柱

1. **環境マップ**（`gl/env.js`）
   起動時に equirect の環境マップを焼き、ラフネス別にぼかしたミップ列を持たせます。
   窓・天井の面光源・暗い作業台という**明暗のコントラスト**を入れてあるのが要点で、
   環境が一様に明るいと金属は白いプラスチックにしか見えません。
2. **Beer-Lambert 吸収**
   カラメルもプリンも液体も、色を直接指定せず `exp(-σ × 厚み)` で決めます。
   薄いところは黄金色、厚いところは焦げ茶。**厚みで色が変わることがカラメルの正体**です。
   係数の比率を上げすぎると緑が先に落ちて赤紫になるので、比率も含めて調整しています。
3. **内部散乱と縁の透過**
   プリンは詰まった塊ではなく、光が通る半透明体として扱います。
   視線方向の見かけの厚みを `dot(N,V)` から出し、薄い縁ほど明るく光らせます。
4. **2 パス屈折**（大穴 P）
   不透明（皿・型・容器）を描いた時点で一度コピーし、屈折する物（プリン・液体・
   注ぐ流れ）がそのコピーをずらしてサンプルします。皿の白がプリン越しに滲みます。

そのうえで、**接地影**（皿のシェーダに円盤遮蔽を入れる）、**色移り**（プリンの黄色が
皿に乗る）、**カラメルの厚み場**（`FS_FIELD` で 512×256 に焼き、法線の起伏まで作る）、
**「す」**（気泡）、**メニスカス**（液面のふちの盛り上がり）を足しています。

### 形は回転体で作る

型・皿・プリン・鍋・ボウル・液面はすべて「断面プロファイルを Y 軸で回す」だけで
作っています（`gl/geom.js`）。プリンの揺れは頂点シェーダの変形関数 1 つで、
法線は変形後の位置の差分から都度求めています。
**流体シミュレーションも soft-body も使っていません。**

### 品質の段階制御

| ティア | 解像度 | MSAA | 屈折 | ブルーム |
|---|---|---|---|---|
| 0 (低) | 0.62× | なし | なし | なし |
| 1 (中) | 0.85× | なし | あり | あり |
| 2 (高) | 1.0× | 4x | あり | あり |

端末の素性で初期値を決め、実測フレーム時間で上下させます（`TierGovernor`）。
22ms 超が続けば落とし、余裕があれば戻します。`?q=0|1|2` で固定もできます。
MSAA はドライバによって RGBA16F のマルチサンプルが通らないので、
フレームバッファの完全性を確認してから使い、駄目なら自動で外します。

工程 9 で初めてシェーダが走るとカクつくので、前半のうちに一度だけ画面外で
全プログラムを走らせて温めています（`Hero.warmup`、大穴 N の実用版）。

## ファイル構成

```
index.html      キャンバス 3 枚（back / gl / front）
styles.css      3 枚重ね・タッチ操作の抑止・セーフエリアの取得
src/light.js    画面全体で共有する 1 つのライトモデル
src/main.js     ループ / 工程の遷移 / 3 層の描画 / 誘導 / 完成画面の UI
src/stages.js   12 工程の定義（back 用 draw / GL 用 gl / front 用 front / 2D 用 fallback）
src/art.js      Canvas2D の描画（背景・小物・WebGL が無いときの Hero）
src/view.js     枠から倍率を決める自動カメラ + 正射影行列
src/input.js    寛容なジェスチャ認識（円 / 一方向 / 弧 / 長押し）
src/audio.js    WebAudio による効果音（外部アセットなし）
src/gl/glx.js     WebGL2 の薄いラッパ・品質ティア・MSAA
src/gl/env.js     環境マップと微細ディテールの焼き込み
src/gl/geom.js    回転体メッシュの生成
src/gl/mat.js     4x4 / 3x3 行列
src/gl/shaders.js GLSL（プリン+カラメル / 金属 / 陶器 / 液体 / 流れ / ポスト）
src/gl/hero.js    Hero レイヤーの描画順・パス構成
tools/bundle.mjs  1 枚の HTML にまとめる
tests/smoke.mjs   1 周プレイして各工程のスクリーンショットを撮る
tests/moment.mjs  「型を抜く 3 秒」だけをコマ撮りする
```

デバッグ用に `window.__game` を公開しています
（`__game.jump('demold')` で任意の工程へ飛べます）。

# 水面ひかり網ラボ

**水面を指で動かすと、水底に映る光の網＝causticsが踊る。**

4歳児のためのモバイルWebゲーム。説明はいりません。画面をさわると、水がゆれて、
底の光がおどります。それだけです。

WebGL2 のみ。ライブラリ・ビルド手順・アセットは一切ありません。

---

## あそびかた

| 操作 | 起きること |
| --- | --- |
| トン、とタップ | まるい波紋 → 水底に光のわっかが広がる |
| 二か所を同時にタップ | 波が重なって、光の模様が複雑になる |
| 指をすべらせる | 指についてくる細長い波 |
| ぐるぐる円をえがく | 渦ができて、光網が花や渦のかたちになる |
| 指をおいたまま | そこから穏やかな波がくりかえし生まれる |
| 指をはなす | 波がしずまり、最後に巨大な光の花が数秒だけ咲く |

水底には半透明の花・星・貝がねむっています。あそんでいるうちに、そこへ光が
集まると、ひらいて光ります。さがすパズルではありません。偶然そうなります。

## 動かす

```bash
npm start          # http://localhost:8080/
```

依存ゼロの静的サーバーです。どんな静的ホスティングにそのまま置いても動きます。

### URL パラメータ

| パラメータ | 意味 |
| --- | --- |
| `?seed=1234` | 毎回変わる要素（底の色・光源方向・隠れた花・減衰・最後の花のかたち）を固定する |
| `?fast=1` | dpr=1・低解像度・ポストなし。E2E 用の決定的モード |
| `?packed=1` | float テクスチャ非対応端末向けの 8bit パック経路を強制する |
| `?view=caustic\|slope\|state\|flow` | シミュレーションバッファを直接表示する（開発用） |
| `?ratio=0.3` | 水槽の縦横比を上書きする（開発用） |

## テスト

```bash
npm start &
npm run smoke     # Chromium で仕様の操作連鎖をひととおり実行して検証
npm run shots     # 各画面サイズのスクリーンショットを tools/out/ に出力
```

`smoke` が検証すること:

- iPhone 縦・iPhone 横・iPad 縦で起動し、JS エラーが出ないこと
- **タップした場所の光網が実際に明るくなること**（局所・複数フレームのピーク比較）
- 円をえがくと模様の分散が上がること
- 乱暴に叩いても値が発散・破綻しないこと
- **誰も触っていない水槽では花が勝手に開かないこと**
- **花の上であそぶと花が開くこと**（ごほうびのループそのもの）
- 指を離したあと、光の花のフィナーレが出ること
- 実行時の品質低下（全バッファの作り直し）で GL エラーが出ないこと
- 8bit フォールバック経路が起動すること

> スモークテストは SwiftShader 上で走ります。**色・なめらかさ・FPS はここでは
> 判定できません**。それらは GPU のある実機で確認してください。

## しくみ

```
touch ─▶ Input（平滑化・振幅制限）
            │
            ▼
        Sim  ── state(h, h_prev) 減衰波動方程式 ─┐
             └─ flow(vx, vy) 渦の場（波を移流）  │
                                                ▼
                                          slope(dh/dx, dh/dz)
                                                │
              ┌─────────────────────────────────┴──────────┐
              ▼                                            ▼
        Caustics（光子スプラット）                    水面シェーダ
              │                                       （屈折・フレネル・鏡面）
              ▼                                            │
        水底シェーダ ──▶ 花・泡 ──▶ 水面 ──▶ Post（ブルーム・トーンマップ）
```

### 光網 — `src/caustics.js`

この作品の心臓部です。ray tracing も Navier-Stokes もしません。

水面に光子のグリッドを置き、各光子を局所の傾きで屈折させて水底に落とし、
**加算合成でスプラット**します。光子の明るさは「もとの水面の面積 ÷ 落ちた先の
面積」。光が収束する場所では何千もの光子が同じ細い線に積み上がって白く焼け、
発散する場所は暗く沈みます。この**細い明線と暗部のコントラスト**こそが
「わあ！きれい！」の正体なので、ここだけは物理どおりに計算しています。

明るさは正規化してあるので、平らな水面はちょうど `exposure` の明るさになり、
それより明るい部分はすべて本物の集光です。分散（赤・青を光の勾配方向にずらして
サンプルする）で、明線に金と水色のふちがつきます。

### 波 — `src/sim.js`

減衰つき2次元波動方程式。干渉（二か所タップ）も自然な収まりかたも、方程式が
勝手にやってくれます。180Hz の固定ステップで、1フレームに3サブステップ。

指で円をえがくと、別に持っている **flow 場**（速度場）に渦が注入されます。
flow は波を移流するので、円形の波紋がそのまま渦を巻いて花のような光網に
変わります。

静止した水面にも、ごく弱いアナリティックなうねりを重ねてあります。これは
「進行波の和の**真の勾配**」として書いてあります。適当な傾き場では回転が
残ってしまい、caustics が嘘くさくなるからです。

### バッファのかたち

シミュレーションバッファも caustics テクスチャも、**水槽の縦横比に合わせて
形を変えます**（テクセル数は一定）。正方形バッファで細長い水槽を扱うと、
奥行き方向の解像度だけが数倍粗くなり、波紋が四角くつぶれます。
ラプラシアンも軸ごとに実際のテクセル間隔で重み付けしてあり、縦持ちでも
波紋はちゃんと円です。

### 乱暴な操作 — `src/input.js`

イベントから直接なにかを注入することはありません。各ポインタは平滑化された
位置・向き・累積回転角を持ち、注入はフレームループから**頻度と振幅を制限して**
行われます。さらに全体の注入エネルギーが増えると新しい波の振幅が下がります。
だから両手でバンバン叩いてもノイズにはならず、豊かで収束したパターンになります。

### 花がひらく条件

GPU から caustics の**集光度マップ**（明るさの二乗平均）を非同期リードバック
（PBO + fence）しています。花は「**誰かがあそんでいる間に**、そこへ周囲平均より
はっきり明るく光が集まったとき」に充電されます。

- あそんでいる signal がないと絶対に充電されない → 放置した水槽では咲かない
- 周囲平均との**比**で見る → 端末の品質設定が変わってもテンポが変わらない

花がひらくと、その花自身が波紋を生みます。原因と結果が、もう一度。

### 端末性能

フレーム時間を監視して、品質を2段階まで**下げるだけ**します（上げないので
振動しません）。下げるとシミュレーション解像度・光子数・描画解像度が落ち、
ポストが切れます。光網の美しさは光子密度とコントラストから来ていて解像度からは
来ていないので、低品質でもちゃんときれいです。

float テクスチャが使えない WebGL2 端末では、RGBA8 に16bit固定小数を手で
パックし、バイリニアも手で行う経路に落ちます（`?packed=1` で強制できます）。

## カメラ

水面から約38°上空に固定。自由操作はできません。水底に大きな模様ができたとき
だけ、ゆっくり少しだけ上昇して全体を見せます。タッチ中は動きません。

画面比に合わせて水槽の縦横比と距離を毎回計算し、iPhone 縦・横、iPad の
どれでも水面と水底が同時に、画面いっぱいに入るようにしています。
